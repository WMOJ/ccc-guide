Suppose a problem gives you a count N on the first line, then N numbers to add up. A loop that calls `input()` once for the count and once for each number reads them correctly, and on a short list it runs instantly. This lesson builds the habit you will use from here on: read everything once, walk the pieces by position, and write everything once.

## How large input gets

A problem's input specification might allow N up to a few hundred thousand values. PyPy, the interpreter the CCC grader runs, manages on the order of `10^7` to `10^8` simple operations a second, the same estimate M2.9 uses. One addition per value, for N up to a few hundred thousand, is a small fraction of that budget. The arithmetic was never going to be the problem. The cost that adds up sits in how the values arrive and leave.

## One call per line, or one call for everything

Every call to `input()` is a separate request to the input stream for the next line. A loop that reads N values that way makes N + 1 calls. With 5 values nobody notices the extra calls. With hundreds of thousands, they cost time the algorithm needs elsewhere.

`sys.stdin.read()` asks for the whole input in one call, as one long string. Then `.split()` breaks that string into a list of tokens wherever there is whitespace. The same input costs one call, however long it is.

Every example in this lesson follows the same shape, the house skeleton:

```python
import sys


def main() -> None:
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    # Parse input_data by position, build a list of results, then write it once.


if __name__ == "__main__":
    main()
```

The `if not input_data: return` line guards a program that has nothing at all to read, before anything else runs.

## Records that carry their own length

Some inputs repeat a record whose length is given inside the input: a count k, then k values, then the next record's count. The pointer handles this with no change in idea. Each time `pos` lands on a count, the loop reads exactly that many tokens, and `pos` is then already on the next count.

The marked range in the figure is one group's values, and the next token after it is always the next group's k. The "Empty group" preset has k = 0: the inner loop reads nothing, the sum is 0, and `pos` moves on to the next count. If the code ever read one token too many or too few, every later group would be misread, which is why `pos += 1` sits right beside each read.

## Building output the same way

Output has the same shape of cost. Calling `print()` once per result sends data out one small piece at a time. Collecting every result into a list as you compute it, then writing the whole list at once, pays the output cost once.

## Getting the details right

`input()` and `sys.stdin.read()` both draw from the same input stream, so mixing them in one program leaves the second reading whatever the first left behind. Pick one for the whole program. Convert each token with `int()` or `float()` as you read it, before you try to add it to anything. Because `write()` never adds its own newline, the join has to supply every line break the output needs, including the final one. On PyPy, this pattern keeps the per-call cost paid once, however many lines the input has.
