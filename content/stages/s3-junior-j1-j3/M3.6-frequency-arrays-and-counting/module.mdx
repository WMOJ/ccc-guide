Imagine you are tracking book titles. You see a list of book IDs, each a number from 0 to 99, and you want to count how many times each ID appears. You could search the list once per ID you care about. There is a faster way: build one array, sized to the range of possible values, and let each value point straight at its own slot.

That is a <Term id="frequency-array">frequency array</Term>. The IDs are 5, 2, 5, 7, 2, 5. Start with an array of 100 zeros, one slot per possible ID. Read each ID in order and add one to its slot: `freq[5]` becomes 1, then `freq[2]` becomes 1, then `freq[5]` becomes 2, and so on. After one pass through all six IDs, `freq[2]` is 2, `freq[5]` is 3, `freq[7]` is 1, and every other slot is still 0.

## Why one pass beats 26 passes

Now suppose you want the count of each of the 26 lowercase letters in a word of length n. The range is small and fixed: a through z. One way is to call `word.count(letter)` for each letter. Each call scans the whole word, so all 26 calls cost 26 times n comparisons, whether or not most letters appear at all. For a word of 200,000 letters that is 5,200,000 comparisons.

A frequency array does the same job with one increment per character: n operations, not 26n. At n = 1,000 that is 1,000 against 26,000. The gap is the number of possible values you would otherwise ask about one at a time. The trick is index arithmetic: the value becomes the position of its own counter, so there is no scanning or key lookup, only a direct index into the list.

## Turning a letter into a slot

For letters a through z, the array needs 26 slots, one per letter. `ord(char)` gives a character's numeric code, and subtracting `ord('a')` turns `'a'` into 0, `'b'` into 1, and so on up to `'z'` at 25. That subtraction converts a value that is not a small integer into one that is, so it can address a slot. The figure shows the first six letters.

## Counting digits

The same pattern works for any small, known range, not just letters. Digits are always 0 through 9, so a digit-counting array needs exactly 10 slots, and the index calculation is even simpler: `int(char)` already gives the slot number directly, no subtraction needed.

## Using the counts once they exist

A frequency array is rarely the end goal. You build it, then read it back, and the reading is often the actual problem. Two readings come up again and again: find the most frequent value, and compare two arrays.

To find the most frequent value, keep a variable `best` holding the slot with the highest count so far, and scan the slots once. Take a list of die rolls, each a face from 1 to 6. The array gets 7 slots, so a face number is its own index and slot 0 goes unused. A slot only takes over when its count is strictly larger, so on a tie the smaller face stays.

## Sizing the array correctly

The array needs a slot for every possible value, indexed from 0: 10 slots for the digits 0 to 9, 26 for the letters, 7 for faces numbered 1 to 6. An array one slot short crashes on the largest value. If the input can include values you did not plan for, filter before indexing, the way `freq_count.py` checks `'a' <= char <= 'z'` first. Uppercase and lowercase letters have different codes, so a problem that mixes cases must decide up front whether they are distinct values or whether everything is converted to one case.

## Keeping it fast on PyPy

Every example builds its array once, as a flat `[0] * 26` or `[0] * 10` list, and updates it with plain index arithmetic, `ord(char) - ord('a')` or `int(char)`, with no dictionary lookup or hash. Each character is read once and writes to exactly one slot, so the build is a single pass with no nested work inside it. The read-back loop runs once over a fixed 26 or 10 slots. A flat list sized to a known range, filled in one pass and read in one pass, is the shape PyPy runs fastest.

## When frequency arrays fit

A frequency array earns its speed from one fact: the range of possible values is small and known ahead of time. Digits, letters, and IDs capped at a fixed maximum all qualify. If the range is enormous but the data is small, an array that size wastes memory. A dictionary, which stores only the values that appear, fits better there. If you do not know the range at all, you cannot size the array, so a frequency array is not yet an option.
