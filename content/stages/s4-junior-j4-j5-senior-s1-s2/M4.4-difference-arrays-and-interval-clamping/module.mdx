Suppose a booking system tracks how many rooms are reserved on each of 100,000 nights, starting from zero. A batch of up to 100,000 bookings arrives, and each one reserves a room for every night in some range. Afterward you need the reservation count on every night. Marking each night of each booking directly can cost a lot. One booking spanning all 100,000 nights, repeated 100,000 times, is ten billion updates, the same wall M4.3's rainfall queries hit before prefix sums. A <Term id="difference-array">difference array</Term> clears that wall the same way. Instead of touching every night in a range, it touches only the two nights where the range starts and stops.

## Recording changes instead of totals

Where a prefix sum array stores a running total, a difference array `diff` stores the change from one position to the next. To add `val` to every index from `l` to `r`, inclusive, write `diff[l] += val` to start the increase and `diff[r + 1] -= val` to cancel it the moment the range ends. When the array is rebuilt later, every index from `l` to `r` has `val` added, and nothing past `r` does, because the `-val` has already undone it.

`diff` needs `n + 1` entries for an array of length `n`, the same convention as M4.3's prefix sum array. The extra slot past the end holds `diff[r + 1]` safely even when `r` is the last index.

Rebuilding is not a new idea: it is M4.3's prefix sum run directly over `diff`. `arr[i]` is the sum of `diff[0]` through `diff[i]`, a running total exactly like the one that built `prefix`. Only what gets summed differs. M4.3 sums the original values to answer range queries. Here, summing `diff` reconstructs the array itself, with every update already folded in.

## Why two writes beat a loop

Each update costs two array writes, O(1), so M updates cost O(M) whatever their ranges. A direct loop that marks every index of every range costs O(M times N) in the worst case. With M and N both at 100,000, that is ten billion operations. The difference array costs O(M) to record the updates plus O(N) for one rebuild pass, O(M + N) altogether: 200,000 operations, which PyPy clears easily.

## Going the other direction

Any array can be turned into a difference array, not only one built from range updates. `diff[0]` copies `arr[0]`, and every later `diff[i]` is `arr[i] - arr[i - 1]`, the gap between neighbors. Running the prefix sum back over that `diff` reproduces `arr` exactly. Subtracting neighbors and prefix-summing undo each other, and `diff[i]` alone is only ever a gap, never a value from the original array.

## Clamping a range to the array

A problem does not always guarantee that a range fits inside the array. A request might ask to reserve nights `-2` to `2`, or `3` to `1000`, when the array only holds indices `0` through `n - 1`. <Term id="interval-clamping">Interval clamping</Term> fixes that before the range reaches `diff`: clip `l` up and `r` down with `l = max(l, 0)` and `r = min(r, n - 1)`. If the clipped `l` is greater than the clipped `r`, the whole range fell outside the array, so skip that update. Writing `diff[r + 1] -= val` with the raw `r` could also write past the end of the list you allocated.

## Getting the boundary right

The `+ 1` on the stop index is the easiest detail to get wrong. `diff[r] -= val` instead of `diff[r + 1] -= val` cancels the increase one index too early, so index `r` never gets counted. M4.3's "One day" case catches the same kind of off-by-one, and a range where `l` equals `r` is the quickest test for a difference array too. A `diff` sized `n` instead of `n + 1` fails the moment an update's `r` is the last index, since `diff[r + 1]` then falls outside the list.

## When to reach for this pattern

Recognize a difference array when a problem hands you many updates to ranges of an array and then asks for the values after every update has been applied. Events that start and end at given points reduce to the same two writes. So do resources reserved and released over an interval, and a count of how many intervals cover each position. The technique inverts prefix sums. A prefix array turns values into fast range sums. A difference array turns range updates into fast reconstruction, and the same running-total pass moves between the two. On PyPy, a flat list for `diff`, one `sys.stdin.read().split()` call for input, and one join for output keep the O(M + N) work free of extra I/O cost.
