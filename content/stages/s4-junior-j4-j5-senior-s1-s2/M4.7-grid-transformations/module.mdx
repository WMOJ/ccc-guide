A photo is 2 rows tall and 3 columns wide, and a photo editor needs to turn it a quarter turn clockwise. Every pixel has to land in a new cell. The pixel in the top-left corner belongs in the top-right corner of the turned photo, and every other pixel moves by one rule. Working out each landing cell by hand invites off-by-one errors. Building the turn from a couple of simple moves is faster and much harder to get wrong.

The simplest of those moves is the <Term id="transpose">transpose</Term>: swap rows and columns, so the cell at row `i`, column `j` moves to row `j`, column `i`. A grid with 3 rows and 5 columns becomes a grid with 5 rows and 3 columns.

## Transpose

Take a 2-by-3 grid:

```
A B C
D E F
```

To transpose it, build a new grid with the dimensions swapped and read column `j` of the original as row `j` of the result:

```
A D
B E
C F
```

## Rotate 90 degrees clockwise

A clockwise quarter turn sends the top row to the rightmost column and the leftmost column to the top row. You can build it from two steps you already have: transpose the grid, then reverse each row. Starting from

```
1 2 3
4 5 6
```

the transpose gives `1 4 / 2 5 / 3 6` (one row per line), and reversing each row gives:

```
4 1
5 2
6 3
```

## Horizontal and vertical reflection

Reflecting horizontally mirrors left to right, so reverse each row. Reflecting vertically mirrors top to bottom, so reverse the order of the rows:

```
A B C       C B A       D E F
D E F  -->  F E D       A B C
  horizontal            vertical
```

## Why these transformations work

Each transformation is a permutation of positions, and each has an inverse. Transposing moves `(i, j)` to `(j, i)`, and doing it twice puts every cell back. Two horizontal reflections, or two vertical ones, also cancel. A quarter turn needs four repeats to return to the start, since it is a quarter of a full circle.

All of them run in `O(R * C)`, since each visits every cell once to build a new grid. Reversing in place would save memory, but a fresh grid is simpler to get right, and at contest sizes the extra memory rarely matters.

## Keeping it fast on PyPy

A 1,000-by-1,000 grid has one million cells, and every transformation here does one pass over them: about one million cell moves, comfortably inside what PyPy finishes in time. The list comprehensions in `transpose.py` and the slice `row[::-1]` in `reflect.py` build a whole row in one expression rather than one statement per cell. Read the grid once with `sys.stdin.read().split()`, and when printing, join each row into one string instead of printing one value at a time.

## Combining transformations

Problems often chain these moves. A 180-degree rotation is two clockwise rotations, calling the same function on its own output:

```python
def rotate_clockwise(grid):
    rows, cols = len(grid), len(grid[0])
    transposed = [[grid[i][j] for i in range(rows)] for j in range(cols)]
    return [row[::-1] for row in transposed]


grid = [[1, 2], [3, 4]]
rotated_180 = rotate_clockwise(rotate_clockwise(grid))
```

Order matters: a reflection followed by a rotation is not the same as that rotation followed by the reflection.

To test whether two grids match under rotation and reflection, generate all eight versions of one grid. These are the four rotations plus the same four after a reflection. Check whether any equals the other grid. Track the dimensions as you chain: every quarter turn swaps the row and column counts, so R by C becomes C by R, then R by C again.

## Getting the details right

The dimension swap is the easiest detail to miss. A rotated R-by-C grid becomes C by R, so allocating the result with the original dimensions raises an index error the moment you write past its shorter side.

Clockwise and counterclockwise are also easy to swap, since both start with the same transpose. Track one corner to check: clockwise puts the 2-by-3 example's top-left value in the new top-right corner, and counterclockwise puts it in the new bottom-left corner.

In-place reversal needs care too. Swap position `i` with position `R - 1 - i` and stop at the midpoint, or you undo every swap you already made. Building a new grid avoids this bug.

## Diagonal reflections

Two more reflections appear less often: across the main diagonal and across the anti-diagonal (top-right to bottom-left). The main-diagonal reflection sends `(i, j)` to `(j, i)`, which is the transpose under another name. The anti-diagonal reflection sends `(i, j)` to `(C - 1 - j, R - 1 - i)`, and you can build it by transposing, then reflecting the result both horizontally and vertically.
