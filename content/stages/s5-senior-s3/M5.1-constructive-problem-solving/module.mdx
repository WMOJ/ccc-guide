Given N and M, build an N-by-M grid of letters where every row has the same number of vowels as every other row. Every column must also share one vowel count, and each row must split exactly in half between vowels and consonants. Report "Impossible" if no such grid exists.

Hold that problem in mind. Nothing here asks for a maximum, a minimum, or a count. It asks you to produce one grid that works, or to prove that none can. A problem phrased this way, "output any valid arrangement," "construct a grid," "find any sequence," is a <Term id="constructive-problem">constructive problem</Term>. You solve it by building an answer directly and checking it against every rule, not by searching a space of candidates for the best one.

## Why a search does not fit

The most direct alternative is <Term id="brute-force">brute force</Term>: try every way to fill the grid with vowels and consonants, and keep the first one that satisfies all three rules. Each of the grid's N times M cells has 2 choices, so the candidate count is 2 raised to N times M, not N times M itself. A 6-by-6 grid already has 2^36, about 6.9 x 10^10, candidates; an 8-by-8 grid has 2^64, about 1.8 x 10^19. PyPy checks on the order of 10^7 to 10^8 simple operations a second, so even the 6-by-6 count alone takes minutes, before a single grid is checked against the rules.

Building the grid directly costs one step per cell, N times M, not 2 to the power of it. That gap only grows as the grid gets bigger, so a construction that reasons out the answer beats a search that tries every answer, however the grid is sized.

## Start from the simplest pattern

The way in is to try the simplest pattern that could possibly work, and complicate it only once that pattern actually fails.

Fill the whole grid with `a`. Every row now has exactly M vowels, a constant across all rows; every column has exactly N vowels, a constant across all columns. Both of the first two rules hold immediately, for any N and M, with nothing to search for.

## Extending the pattern for the third rule

The third rule, that each row splits exactly in half, breaks the all-`a` grid at once: a row of all vowels has zero consonants. Complicate the pattern only as far as the new rule demands.

Splitting a row in half needs M to be even; an odd M cannot divide into two equal integer halves no matter how the letters are arranged. So try a checkerboard: make cell (row, col) a vowel when row plus col is even, a consonant otherwise. Since M is even, exactly half of any row's column indices are even and half are odd. Every row lands at exactly M / 2 vowels and M / 2 consonants, satisfying the third rule directly by construction.

## Why this construction is correct

Two questions decide whether a grid of size N by M can satisfy all three rules, and both have short answers.

First, M must be even, for the reason above: a row of odd length cannot split into two equal halves.

Second, given M is even, N must also be even. Every row holds exactly M / 2 vowels once the third rule holds, so the whole grid holds N times M / 2 vowels in total. If the second rule holds too, that same total splits evenly across the M columns, so each column holds exactly (N times M / 2) / M vowels, which reduces to N / 2. That is only a whole number when N is even. So whenever N is odd, no arrangement of any kind, checkerboard or otherwise, can satisfy the second and third rules together: the total forces a fractional column count.

Both conditions are also enough. When N and M are both even, the checkerboard already gives every row exactly M / 2 vowels. Running the same counting argument forward shows every column lands at exactly N / 2 vowels too. N even and M even is therefore not just necessary, it is sufficient, and the checkerboard is the witness that proves it.

## Symmetry cuts the choices in half

## Keeping it fast on PyPy

Every example above reads its input once with `sys.stdin.read().split()`. `grid_vowels.py` builds each row as a list of characters and joins it once with `"".join()`. PyPy has no in-place string append, so joining once beats concatenating one character at a time. The whole grid is collected into a list and printed with a single `"\n".join()` call instead of one `print()` per row. That keeps output cost proportional to the grid's size, not to the print-call count. None of the three examples searches, recurses, or keeps more state than the grid itself.

## Putting it together

A constructive solution almost always follows the same shape: try the simplest pattern that could satisfy every rule, and check it. When a rule breaks the simple pattern, look for the smallest change that repairs it, the way the checkerboard grew out of the all-vowel grid. If no repair works, look for a counting or parity argument, like the one above, that rules out every possible arrangement at once. Build in symmetry wherever a rule allows it, since it removes half the decisions before you make them. Then check the result independently, the way a grader would, before it ever reaches the judge.
