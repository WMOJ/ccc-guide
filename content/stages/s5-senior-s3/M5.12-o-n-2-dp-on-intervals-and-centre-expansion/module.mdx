An engraver checks a word before cutting it into a plate, since a palindrome reads the same
engraved forwards or backward and looks deliberate rather than accidental. Given a word, what is
the longest palindrome hidden inside it, and how many different palindromic substrings does the
whole word contain? Both questions use <Term id="center-expansion">center expansion</Term>: grow
outward from a candidate center, one character at a time, for as long as the characters on each
side keep matching.

## Checking every substring directly

A substring runs from some start index to some end index, so there are O(N^2) substrings in a
word of length N. Checking whether one substring is a palindrome, by comparing it to its own
reverse, costs O(N) in the worst case. Checking all of them this way costs O(N^3): for a word of
5,000 characters, that is on the order of 1.25 * 10^11 character comparisons, far past what a
judge's time limit allows. The insight that brings this down to O(N^2) is the same one M4.11 used
for staircases and coins. A palindrome check on a substring reuses the check already done on the
substring one step smaller inside it, instead of starting over.

Both approaches look at essentially the same O(N^2) substrings or centers. The difference is the
cost of handling each one. Re-verifying a substring from scratch costs O(N). Reusing a smaller
answer already computed, either through the table or through an expansion that stops the instant
it can, costs O(1) amortized instead.

## Center expansion

A palindrome has a center: a single character for an odd-length palindrome, or the point between
two characters for an even-length one. Expanding outward from a center compares the characters on
each side one pair at a time, and stops the moment they differ or the string runs out.

## The interval DP recurrence

The same problem also fits a table. Let `is_pal[l][r]` be true when the substring from index `l`
to `r`, inclusive, is a palindrome. A length-1 substring is always a palindrome. A longer one is a
palindrome exactly when its two ends match and the substring one step in from each end,
`is_pal[l+1][r-1]`, is also a palindrome. That is the same subproblem structure M4.11's bottom-up
table used for smaller stairs.

Filling `is_pal[l][r]` needs `is_pal[l+1][r-1]` to already be filled, and that inner interval is
always two characters shorter. Filling the table in order of increasing length guarantees every
cell's dependency is ready first. That is the same way M4.11's bottom-up table filled small stairs
before the ones that depend on them. Filling by `l`, or by `r`, instead would reach some cells too
early.

<Figure caption="Filling is_pal by increasing length: length 1 first, then each later length using an arrow back to the interval two characters shorter">

</Figure>

`"redder"` shows the dependency chain directly: `is_pal[2][3]` (`"dd"`) is true at length 2, which
makes `is_pal[1][4]` (`"edde"`) true at length 4, which makes `is_pal[0][5]` (`"redder"`, the whole
word) true at length 6. Every other cell above stops at false the moment its ends differ or its
inner cell is false, without needing to look any further inward.

The same length-first order applies to any interval DP, not only palindromes. A picture of the
fill order for a general table makes the dependency direction clear on its own.

shortest first, is the one order that never asks for a cell that is not there yet.

## Counting instead of just the longest

Center expansion answers "what is the longest palindrome," one center at a time. The `is_pal`
table answers a different question just as easily. Count every `True` cell, and the result is
the total number of palindromic substrings, not just the longest one. `interval_palindrome.py`
above does exactly that. It prints every palindromic substring of `"redder"` as it is found, and
a running total, `9`, six single characters plus `"dd"`, `"edde"`, and `"redder"` itself.

## Avoiding the full table

An `is_pal` table costs O(N^2) memory, one boolean per interval, which is fine for N up to a few
thousand. Some interval DP problems store a number instead of a boolean at each cell. An O(N^2)
table of Python objects can then be too large to fit, even where the arithmetic itself would be
fast enough.

Center expansion never needed the table at all. Track only the longest palindrome length found at
each center, and that answers "what is the longest palindrome in the whole word." A single array
of size N holds it. That is exactly what center expansion already computes.

shorter palindromic substrings it also contains.

## Getting these right

Handle even-length centers separately from odd ones. A loop that only checks single-character
centers misses every palindrome of even length, such as `"deed"`, which has no single character in
the middle. The `expand` function shown above takes the pair of starting indices as arguments, so
the exact same code handles both: `(i, i)` for odd, `(i, i + 1)` for even.

Keep the two ends of an interval matched to the direction the recurrence actually depends on.
`is_pal[l][r]` depends on `is_pal[l+1][r-1]`, the interval one step in from both ends. It does not
depend on `is_pal[l+1][r]` or `is_pal[l][r-1]`, which drop only one end and describe a different,
shorter substring entirely.

On PyPy, a flat list of length `N * N`, indexed as `row * N + col`, runs faster than a list of
lists for a large `is_pal` table, since each lookup is one array index instead of two. Center
expansion needs no such table at all. That is one more reason to reach for it first whenever the
question is about the longest palindrome rather than every one of them.
