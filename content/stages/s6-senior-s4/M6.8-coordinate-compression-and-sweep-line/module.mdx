A café lists the shifts its staff work on one long day, measured in seconds, so a shift runs from a start to an end somewhere in the range 0 to 10^9. The owner wants two numbers: how many seconds at least one person is on duty, and the most people on duty at the same moment. Up to 100,000 shifts can overlap in any pattern.

Checking every second against every shift would take 10^9 times 100,000 steps. Even writing one flag per second needs a billion-slot array. The way out is to notice that the picture only changes when a shift starts or ends. A <Term id="sweep-line">sweep line</Term> walks those change points in sorted order and keeps a running count of how many intervals are open. The second half of the lesson carries the same idea to rectangles, where <Term id="coordinate-compression">coordinate compression</Term> shrinks a plane with coordinates up to 10^9 to a small grid.

## Sweeping along one line

Turn each shift into two events: a `+1` at its start and a `-1` at its end. Sort the events by position. Between two neighboring events no shift starts or ends, so the set of open shifts, and therefore `active`, cannot change. That is why one pass is enough: each stretch between neighboring events is either covered the whole way (`active` above 0) or not at all.

Sorting tuples compares the position first and then the change. At the same position `(4, -1)` comes before `(4, 1)`, so an interval that ends where another begins is closed before the next one opens, and `best` does not count them as overlapping. The "Touching" preset shows this: its largest `active` is 1. A covered stretch adds its own length once, however large `active` is. Adding `active` times the length would give the sum of the interval lengths instead, which needs no sweep at all.

The work is one sort of 2n events plus one pass. That stays fast in PyPy because the events sit in a flat list of small tuples and the loop does only additions and comparisons.

## Rectangles on a huge plane

The same question in two dimensions asks how much area a set of axis-aligned rectangles covers, and how much of it lies under two or more. Coordinates run to 10^9 and there can be 1,000 rectangles, so a unit grid has 10^18 cells. M4.14 already showed the remedy. Replace each distinct coordinate by its rank in sorted order through a dictionary, and keep the sorted list so you can recover the original coordinate. The rectangles' corners contribute at most 2,000 distinct x values and 2,000 distinct y values, so the compressed grid has about 4 million cells instead of 10^18.

Area survives compression only if you keep the gaps. The width of the column between rank `i` and rank `i + 1` is `xs[i + 1] - xs[i]`, and rows work the same way. Here are three rectangles with small numbers so the grid fits on a screen. The same program works unchanged if every coordinate is multiplied by 10^7, because only the order and the gaps matter.

The last width and height are blank because the last coordinate has no neighbor after it. A rectangle whose corners have x ranks 0 and 3 covers the cells in columns 0, 1 and 2, three columns, because a rank names a boundary and a cell sits between two boundaries. Why is one number per cell enough? No rectangle edge lies strictly inside a compressed cell, because every edge is one of the boundary coordinates. So every point inside a cell is covered by the same set of rectangles, and the cell's area times its depth gives its share of the answer exactly.

Painting cell by cell is correct but costs one step per covered cell. With 1,000 rectangles, each spanning up to 2,000 by 2,000 cells, that is up to 4 billion steps. The remedy is the difference array from M4.4, in two dimensions.

## Four marks per rectangle

Instead of touching every cell, put four marks in a `diff` table that is one row and one column bigger than the cell grid. Add `+1` at the top-left corner, `-1` at the top-right, `-1` at the bottom-left and `+1` at the bottom-right. A running sum, the same two-dimensional prefix sum as M4.3, then spreads each rectangle's `+1` over exactly its cells. Watch the marks go in, then the running sum turn them into depths one row at a time.

The compressed grid has at most 2n by 2n cells, so building the table and summing it costs about 4n² operations, roughly 4 million for n = 1,000. That is a few million passes of plain integer arithmetic over lists of lists, the kind of loop PyPy runs quickly.

## When to reach for each

Use a sweep line when the question is about one axis and the natural events are starts and ends: busiest moment, covered length, who is open when. Use compression with a difference array when the question is about area or overlap in a plane. It fits when n is about a thousand or two, so a 2n by 2n table is small. If a query asks about a coordinate the input never mentioned, add it to the sorted list first or look it up with `bisect` as M4.14 shows. Larger n needs a sweep over one axis with a segment tree over the other, which comes in M7.1.
