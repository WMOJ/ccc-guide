A row of tiles has heights `4 7 1 3 5 2`. You want to know how many stretches of neighboring tiles have an average height of exactly 3. The tile `3` alone counts. So do the three tiles `1 3 5`, because 1 + 3 + 5 = 9 and 9 / 3 = 3.

The question gets hard when the row has 200,000 tiles. A stretch is fixed by its two ends, and the heights can be large, so the sums cannot index an array. This lesson combines <Term id="prefix-sum">prefix sums</Term> from M4.3 with the dictionary from M4.1. The dictionary is keyed by a prefix sum and remembers what happened at earlier positions with that same sum.

## Checking every stretch

The direct way tries every pair of ends and keeps a running total for each start. To avoid fractions, it compares the total with `target * length`.

A row of n tiles has n * (n + 1) / 2 stretches. For n = 200,000 that is about 2 * 10^10, far more than the 10^8 or so simple operations a program can afford (M2.9). The loop repeats work, because neighboring stretches share most of their tiles.

## Turning an average into a sum of zero

Subtract the target from every height. A stretch of length `len` has original sum `s`. After the subtraction its sum is `s - target * len`, which is 0 exactly when `s / len` equals the target. So "average equals the target" becomes "sum equals zero", and every number stays an integer, so nothing is rounded.

Now use prefix sums on the shifted values. The sum of the stretch from element `i` to element `j - 1` is `prefix[j] - prefix[i]`, and it is zero exactly when the two prefix values are equal. Counting the stretches means counting pairs of equal prefix values.

## Counting in one pass

Finding equal pairs does not need a second loop. Keep a dictionary `seen` from each prefix value to how many times it has appeared so far. At each element, look up the new prefix value. Each earlier prefix with the same value ends one matching stretch at this element, so its count is added to the answer. Then the count for this value goes up by one.

The dictionary starts as `{0: 1}`. That entry stands for the empty prefix before any element. Without it, a stretch that begins at the first tile has nothing to pair with, and every such stretch is missed.

## Why a dictionary and not an array

With heights up to 10^9 and 200,000 tiles, a prefix value can reach about 2 * 10^14 in size, so an array indexed by sum is out of the question. The dictionary holds only the values that actually appear, at most n + 1 of them. Each element costs one lookup and one store, about 4 * 10^5 dictionary operations for 200,000 tiles, and on average each is constant time. On PyPy a dictionary with integer keys is compact, and the loop above has no other work to slow it down.

The `seen.get(prefix, 0)` call returns 0 for a missing key, so the same lines handle a first visit and a tenth.

## Keeping a best value per key

A count is one thing to store under a prefix value. A DP value is another. Suppose you want the most non-overlapping stretches with average exactly 3. Let `dp[j]` be that number for the first `j` tiles. Either tile `j` ends no stretch, and `dp[j]` equals `dp[j - 1]`, or a stretch ends there. A stretch ending at `j` starts after some earlier position `i` with `prefix[i] == prefix[j]`, and then `dp[j]` is `dp[i] + 1`.

Because `dp` never decreases as `j` grows, the latest earlier position with a given prefix value has the largest `dp`. The dictionary `best` therefore stores, for each prefix value, the `dp` value at its latest position, and the transition is one lookup.

## When to reach for it

Use this pattern when a question is about stretches that hit a target sum, or a target average after shifting, and the sums are too large for an array. Each position asks the dictionary about earlier positions with the same prefix value, then stores what later positions will want to know.
