A weather station keeps a log of `n` daily temperatures. The log never changes, but people keep asking the same kind of question: what was the coldest day from day `l` to day `r`? With a dozen questions you would just scan the range each time. With 200,000 days and 200,000 questions, scanning costs up to 2·10^5 × 2·10^5 = 4·10^10 comparisons, far more than the 10^8 or so simple operations a solution can afford (M2.9).

A segment tree from M7.1 answers each question in about 18 steps (log₂ of 200,000) and also handles changes to the log. When nothing changes, a <Term id="sparse-table">sparse table</Term> does better: it spends `n log n` steps once, then answers every question with two lookups. It is the doubling idea from M6.12 applied to ranges instead of jumps.

## Blocks whose length is a power of two

Write `sp[k][i]` for the minimum of the block of `2^k` elements starting at position `i`. Level 0 is the array itself: blocks of length 1. A block of length `2^k` is two blocks of length `2^(k-1)` placed side by side. In M6.12, `up[k][v]` was two jumps of half the size, one after the other. Here `sp[k][i]` is two blocks of half the length, one after the other:

`sp[k][i] = min(sp[k-1][i], sp[k-1][i + 2^(k-1)])`

A block must fit inside the array, so level `k` only has starts `i` from 0 to `n - 2^k`. The table is built level by level, and each level is one pass over the level before it.

## Answer a query with two blocks

A query range `[left, last]`, inclusive on both ends, has length `last - left + 1`. Pick the largest `k` with `2^k` at most that length. Two blocks of length `2^k` then cover the range: one starts at `left`, the other ends at `last`. Together they leave no gap, and they may overlap in the middle.

To find `k` without a loop, use `length.bit_length() - 1`. A number's bit length is the number of binary digits it takes, and the largest power of two at most `length` has one fewer digit than that.

## Why overlap is safe only for some operations

The two blocks cover every cell of the range at least once and no cell outside it. A cell in the overlap is counted twice. For a minimum that changes nothing: `min(x, x)` is `x`, so the smallest value in the range is still the smallest. Maximum and gcd behave the same way. An operation with that property is called idempotent. It also needs to be associative and commutative, as min, max and gcd are.

A sum is different. The overlap would be added twice. The figure shows the same range three ways, and the sum is the only one that goes wrong.

## Why it covers the range, and what it costs

Let the length be `L`, with `2^k <= L < 2^(k+1)`. The first block ends at `left + 2^k - 1`, which is at most `last`, so it fits. The second block starts at `last - 2^k + 1`. Because `L` is less than `2 * 2^k`, that start is at most `left + 2^k`, the cell right after the first block, so there is no gap between them.

The build costs `n * LOG` operations and as many table entries. A query costs two lookups and one combine. That is worse to build than a segment tree, which builds in `n` steps, but it answers in constant time instead of logarithmic time. The price is that a changed element means rebuilding the levels above it, so a sparse table is for data that stays fixed.

## Making it fast on PyPy

The table is a list of lists of plain integers, which PyPy stores compactly. Build each level in one pass over the level before it, reading input once with `sys.stdin.read().split()` and writing all answers with one `sys.stdout.write`. For 2·10^5 queries, the two lookups and one combine per query are a few operations each.

## When to reach for it

Use a sparse table when a problem asks many minimum, maximum or gcd queries over ranges of an array that never changes. If the array is updated between queries, use a segment tree instead.
