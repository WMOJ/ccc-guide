Suppose you open a textbook or a reference page and its solution is in C++. It starts with `vector<int> a(n);`, reads the values in a `for (int i = 0; i < n; i++)` loop, and ends with `cout << total << "\n";`. You know the algorithm, and the notation is what stands in the way. This lesson maps what you see in C++ to the Python you already write, so you can read that code. It does not run or compile anything, and it says nothing about which language to write in. Each C++ snippet below is short and not run. Each Python side is a file you can read with its output.

## The same program in two notations

Here is a program that reads N and then N integers and prints their sum.

<Code file="examples/cpp_vs_python.py" showOutput caption="Read N integers and print their sum" />

The C++ version reads with `cin` and declares a type for every variable.

```cpp
int n;
cin >> n;
int total = 0;
for (int i = 0; i < n; i++) {
    int x;
    cin >> x;
    total += x;
}
cout << total << "\n";
```

`for (int i = 0; i < n; i++)` has three parts: a start, a condition checked before each pass, and a step after each pass. It is `for i in range(n)`, with indexes from 0 to `n - 1` as in Python. `cin >> x` reads the next whitespace-separated token and converts it to `x`'s type, which is the job of `int(tokens[pos])` in the Python file.

## Integers have a width in C++

A Python `int` grows as large as it needs to. A C++ `int` has a fixed width, usually 32 bits, so it holds only the values from -2147483648 to 2147483647. `long long` has 64 bits and reaches about `9.2 * 10^18`. Going past the top of the range is called overflow. For signed types the C++ language leaves the result undefined. On ordinary hardware the value usually wraps around to the other end of the range. `unsigned` types are defined to wrap. The Python file below models the usual 32-bit wrap with arithmetic, and it says so in a comment.

## Division and remainder on negative numbers

C++ integer division drops the fraction, which rounds toward zero. Python's `//` rounds down, toward negative infinity. The two agree when the exact quotient is positive and differ when it is negative. The remainder follows its quotient: in C++ `a % b` takes the sign of `a`, and in Python it takes the sign of `b`. Both languages keep `q * b + r` equal to `a`; they choose a different `q`. This is why C++ code that needs a non-negative remainder writes `((a % m) + m) % m`, and why the same wrap in Python is just `a % m`.

## References and copies

A C++ function parameter written `vector<int> v` receives a copy of the argument. One written `vector<int>& v` receives the caller's own vector, so changes inside the function are visible outside, and `const vector<int>& v` promises not to change it. Python passes every argument as a name for the same object. Changing a list inside a function changes the caller's list, like the `&` form, and a copy has to be made on purpose.

<Code file="examples/pass_by.py" showOutput caption="A function that edits the caller's list, and one that works on a copy" />

Integers behave like the copying form: `x += 1` inside a Python function rebinds the local name and leaves the caller's number alone.

## Everyday calls

Most of what is left is vocabulary. `v.size()` is `len(v)`, and `v.push_back(x)` is `v.append(x)`. `sort(v.begin(), v.end())` sorts the whole vector in place, like `v.sort()`, and `v.begin()` and `v.end()` are the two ends of the range to sort. A range loop, `for (int x : v)`, is `for x in v`, and `auto` asks the compiler to fill in the type, so `for (auto x : v)` reads the same way. `pair` members are `.first` and `.second`, which are `[0]` and `[1]` on a tuple. A C++ `string` can be changed in place, and `s[i]` is one character that you can do arithmetic on, where a Python `str` is immutable.

## Reading unfamiliar code

Read a C++ type from the outside in. `vector<vector<int>>` is a list of lists, and `map<string, vector<int>>` is a dictionary from strings to lists of integers. Then check the three places where the two languages disagree: how wide the integers are, which way division rounds, and which order a container iterates in.
