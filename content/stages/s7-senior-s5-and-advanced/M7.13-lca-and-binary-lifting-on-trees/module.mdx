Two files sit somewhere in a folder tree, and you want the deepest folder that holds both. That folder is the <Term id="lowest-common-ancestor">lowest common ancestor</Term> of the two nodes, the LCA for short: the deepest node that is an ancestor of both. A node counts as its own ancestor, so if one file's folder contains the other file's folder, that folder is the answer. A problem may ask for this for 2·10^5 pairs of nodes on a tree of 2·10^5 nodes. This lesson answers each pair with the doubling table from M6.12, on a tree rooted the way M5.8 rooted one.

## Parent and depth from a BFS

Root the tree at node 0 with the iterative BFS from M5.8, filling `parent` and `depth`. The one new choice is the root's parent: set `parent[0] = 0`. A jump that would pass the root then lands on the root and stays there, the same way M6.12's dead-end station points to itself. No lookup ever leaves the table, and the query code needs no special case for the top.

## Walk up until they meet

The direct method uses only `parent` and `depth`. While one node is deeper, move it to its parent. When the depths match and the nodes still differ, move both up together until they are the same node. Step through it below on a tree of nine nodes, each labeled with its depth. ## The ancestor table is M6.12's table

M6.12 built `up[k][v]`, the node reached after `2^k` jumps from `v`, with `up[k][v] = up[k-1][up[k-1][v]]`. Here `up[0]` is the `parent` list, and `up[k][v]` is the ancestor `2^k` levels above `v`, or the root if the tree is not that tall. The table needs `LOG` levels, and `LOG = max(depth).bit_length()` is enough, because every depth difference is below `2^LOG`.

## Equalize the depths

Let `a` be the deeper node and `diff = depth[a] - depth[b]`. Climb `a` by `diff` levels with M6.12's bit walk: for each bit `k` that is set in `diff`, replace `a` with `up[k][a]`. Climbing 1 level is one lookup, and climbing 6 levels (binary 110) is two. If `a` and `b` are now the same node, `b` was an ancestor of `a` and that node is the answer.

## Jump together from the highest level

Otherwise the two nodes sit at the same depth, in different branches below their LCA. Try the levels from the highest `k` down to 0. At each level, compare `up[k][a]` and `up[k][b]`. If they differ, both jumps stay below the LCA, so take them both. If they are the same node, the jump reaches the LCA or passes it, so leave `a` and `b` where they are. After level 0, `a` and `b` are different children of the LCA, and the answer is `up[0][a]`.

Step through this on the same tree. The uneven preset starts with the shallower node first, and the ancestor preset ends right after the climb.

Why is the high-to-low order right? Say both nodes are `t` levels below their LCA, with `t` at least 1. A jump of `2^k` levels lands on different nodes exactly when `2^k` is less than `t`, because only then does it stop below the LCA. So the test asks whether `t - 1` still contains `2^k`, and taking the levels from the top writes `t - 1` in binary one digit at a time. The nodes end `t - 1` levels up, which is one level below the LCA.

## Distance between two nodes

The last column of the output comes from one line: `depth[a] + depth[b] - 2 * depth[lca]`. The path from `a` to `b` goes up to the LCA and down again. Both depths count the edges from the root down to the LCA, which are not on that path, so the formula subtracts them twice.

## Making it fast on PyPy

With 2·10^5 nodes and `LOG` = 18, the table has 3.6·10^6 entries. Building each level with one list comprehension over the previous level keeps the work at that many lookups. A query makes under 100 lookups, so 2·10^5 queries cost under 2·10^7. Read all input at once, collect the answer lines, and write them once. The BFS is iterative, so a path-shaped tree of 2·10^5 nodes is no problem.

## When to reach for it

Use it when a tree is fixed and many pairs of nodes are asked about: who is their common ancestor, or how far apart are they. The same table answers "the ancestor `d` levels up" directly, which is M6.12's jump query on the parent list.
